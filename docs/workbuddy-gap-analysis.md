# futureAgent 对标 WorkBuddy：差距分析与功能路线图

> 生成时间：2026-09-02 · 基于代码全量梳理 + WorkBuddy 公开产品信息
> 结论先行：**产品骨架已经达到 WorkBuddy 的"工作台"层面，但"AI 交付能力"和"自动化能力"两条主线尚未真正落地**。当前最大的问题是：经营/汇报智能体的"AI"是确定性模板回复，不是大模型；没有定时任务；没有多模态交付物。

---

## 1. WorkBuddy 是什么

WorkBuddy 是腾讯云（CodeBuddy 团队）推出的 AI Agent 办公工具，定位"AI Agent 办公新范式"，核心卖点：

1. **自主任务规划与交付**：自然语言下达任务，AI 自主理解、拆解、执行，像"AI 同事"
2. **多模态交付物**：自动生成文档、表格、图表、PPT 等可视化办公成果
3. **多 Agent 并行**：多个智能体同时处理不同任务
4. **自动化**：定时任务、工作流沉淀、技能复用，7×24 主动产出
5. **远程协作**：手机发指令、电脑执行；企业微信/QQ 集成
6. **文件处理**：自动整理、命名、格式转换
7. 多格式文件理解（自然语言操控电脑处理文件）

## 4. 重点功能模块建议（按优先级）

### P0 —— 补齐"真 AI + 自动化"，否则只是治理型工作台

1. **经营/汇报智能体 LLM 化 + RAG**
   - 现状：`_deterministic_reply`（business_routes.py:1051 / report_routes.py:1634）模板拼装，知识库内容只在回复里"点名"。
   - 做法：复用 `core/model_hub.py` 路由 + `agent_engine` 的工具循环，把知识库检索做成一个 MCP/内置工具；用 pgvector 建embedding 表（compose 里 `pgvector/pgvector:pg17` 已就位），附件入库时切块向量化（`_extract_attachment_text` 已产出文本）。
   - 保留现有确定性模式作为"未配置模型时"的降级。

2. **定时任务与自动化调度**
   - 现状：无任何调度；日报 `daily_reports` 只能手动点"生成"。
   - 做法：引入 APScheduler（单进程够用，避免上 Celery 的复杂度），新增 `scheduled_jobs` 表（cron 表达式、任务类型：日报生成/数据源拉取/预警扫描/报告推送），管理端给开关。这是 WorkBuddy "7×24 主动产出"的核心。

3. **交付物中心（多模态产出）**
   - 现状：agent 只能通过 MCP `write_file` 写文本，无 xlsx/docx/pptx/图表能力，成果埋在任务 Drawer 里。
   - 做法：①新增"交付物"表（task_id、类型、文件、预览）+ 独立画廊页；②内置工具 `make_xlsx/make_docx/make_chart`（openpyxl + python-docx + matplotlib，纯 Python 无外部依赖风险）；③执行完成后自动把产物登记为交付物并支持预览/下载。

4. **通知中心**
   - 现状：预警/审批/执行结果全靠用户主动刷新页面。
   - 做法：站内通知表 + 顶栏红点 + 通知抽屉；Webhook/企业微信/飞书 bot 出口可配置。审批请求（计划待批准）必须有推送，否则治理流程没人知道该他批了。

### P1 —— 体验与智能升级

5. **多 Agent 并行执行**：放开工作区并发限制到可配置值，看板/工作模式支持同时跑多个 step 的 run；前端 run 列表已支持（`agent_runs` 表结构无需改动）。
6. **工作流沉淀**：把"计划模板"升级为可保存的自动化流程（触发器：手动/定时/webhook），本质是 P0-2 调度器之上的产品化。
7. **启用 LangGraph checkpointer + 上下文压缩**：`AsyncPostgresSaver` 已导入未用；给 `/v1/chat/agent` 传入 checkpointer 实现跨请求线程记忆，长会话用摘要压缩替代"最近 12 条"平铺（`routes.py:629`）。
8. **文件智能解析**：PDF 用 pypdf 提文本、图片走 OCR（或交给多模态模型），补全 `_extract_attachment_text`。
9. **IM 集成**：企业微信/飞书群机器人 Webhook 出口（配合通知中心）；入站指令可先做"邮件/IM → API ingest token"的最小闭环。
10. **消息分页 + 全局搜索**：`GET /conversations/{id}/messages` 加 `before`/`limit`；新增工作区级搜索 API（任务/对话/附件文件名）。

### P2 —— 打磨

11. 看板拖拽换列（dnd-kit）、日历视图（due_date 已有字段）、任务评论。
12. 暗色模式（antd `theme.darkAlgorithm` + CSS 变量分层）、i18n 框架。
13. PWA manifest + service worker。
14. 管理端补全：创建用户、重置密码、工作区增删、审计过滤（时间范围/动作/操作者，当前固定 200 条）。
15. 上线安全清单落地（README 已列：限流、恶意文件扫描、S3、TLS、备份、默认凭据轮换）。
